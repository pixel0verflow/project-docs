specula-index

A weekly film and series title index built from Wikidata, published as release assets · 🟢 Active (main at 606fcda, first build running, 2026-10-14)

Repo: github.com/thirdshift-inc/specula-index (public, MIT; data CC0 from Wikidata)

1. Problem statement — why?

Specula needs to find a film or series by name, offline, and map it to IMDb, TMDB and TVDB ids without a commercial metadata licence. Wikidata is CC0, so a builder can query it, compile a compact binary index, and publish it weekly for the app to download.

2. Features

  • Builder (python -m specula_index.build): 30 SPARQL queries against QLever's Wikidata endpoint, answers cached, then two packs and a manifest.
  • Core pack: one record per title (Wikidata, IMDb, TMDB, TVDB ids, label, year, kind, seasons, genres, fame from sitelinks), sorted search keys, word starts. Flags: bit 0 id overflow, bit 1 TMDB_OTHER_KIND (a TMDB id taken from the other kind).
  • Details pack: up to eight cast, directors, companies, broadcasters, series, franchise, countries, running time, episodes; entities searchable by English name with reverse postings in fame order.
  • Manifest: version, tag, build time, Wikidata snapshot, licence, attribution, and per pack sizes and SHA-256 (raw and gzip), row counts and key counts.
  • Adult titles excluded by class and genre; a real build is refused under 100,000 core records or a drop of more than 10 % from the previous release.
  • Workflows: weekly build and release (index-<date>, marked latest, the five newest kept), a keep-alive job that re-enables the schedule through the API instead of a heartbeat commit (owner's decision, 2026-10-14), PR CI; actions pinned to commits.

3. Architecture overview

QLever SPARQL ─▶ extract.fetch_all (.qlever-cache/*.tsv) ─▶ extract.load (join, shape, drop adult)
   ─▶ pack.core_pack / pack.details_pack (SPTI, format 1, little-endian) ─▶ gzip
   ─▶ manifest.write (verify hashes) ─▶ floor.check ─▶ gh release create index-<date>

Python standard library only. A bundled fixture (tests/fixture/raw) builds deterministically for tests; tests/packreader.py reads both packs back.

4. Problems to solve / known limitations

  • A same-day rebuild fails on the existing index-<date> tag.
  • The first real build is also the first run of the newer SPARQL queries; an empty or failed answer there is a builder finding.
