specula-addons

First-party add-on manifests for the Specula player, with a schema and a validator · 🟢 Active (scaffold awaiting the owner's review and first push, 2026-10-14)

Repo: github.com/thirdshift-inc/specula-addons (public, MIT)

1. Problem statement — why?

Specula reads add-on manifests to draw rows on its Home screen. First-party add-ons need a public, stable address and a check that they never declare content (streams or catalogues). This repository holds those manifests, a JSON schema for them, a validator that enforces the first-party rules, and a GitHub Pages site that serves them.

2. Features

  • Trending manifest (site/trending/manifest.json, id sh.thirdshift.specula.trending): a Home row of trending titles, filled by the metadata providers the user set up in Specula; options for providers, media and window.
  • JSON schema (schema/manifest.schema.json) checked by a small in-repo checker that refuses any keyword or type it does not implement.
  • Validator (python -m addon_manifest.validate site): ids under sh.thirdshift., no stream or catalog resource, no catalogues, duplicate JSON keys refused, option and row cross-references checked. subtitles and meta resources are allowed.
  • CI on pull requests and branch pushes; a test that every workflow action is pinned to a full commit id.
  • Pages deploy on push to main: tests, validator, then the site/ directory is published.

3. Architecture overview

site/<addon>/manifest.json ─▶ addon_manifest.validate ─▶ schema.Checker + first-party rules
                                         │
             .github/workflows/pages.yml ┴▶ upload-pages-artifact ─▶ deploy-pages
             https://thirdshift-inc.github.io/specula-addons/<addon>/manifest.json

Python standard library only; no dependencies.

4. Problems to solve / known limitations

  • The README is still a skeleton of headings; the owner writes it.
  • The first Pages run on main fails until Pages is switched on with GitHub Actions as its source; it then needs one manual run.
  • The schema has no specula.discovery; it is added only if a first-party add-on ever needs it.
