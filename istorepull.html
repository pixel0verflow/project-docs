iStorePull

ipatool without authentication · 🟢 Active / 🔵 Released v0.2.1

Repo: github.com/pixel0verflow/iStorePull

1. Problem statement — why?

The App Store only ever offers an app's latest build, yet Apple still serves older builds an account has been entitled to. Pulling them normally requires a tool like ipatool — but Apple's login (GrandSlam SRP + FairPlay-SAP token minting) needs Apple's private key material and cannot be reproduced by third parties; the legacy password-auth endpoint was retired mid-2026.

iStorePull sidesteps login entirely: the user supplies a real session captured from Apple Configurator, and the tool replays the well-understood store endpoints to list versions and download IPAs. The hard, fragile part (auth) is done by Apple's own signed software; iStorePull only borrows the resulting token.

2. Features

  • capture — embedded selective-MITM proxy auto-extracts the session from a Configurator download. Decrypts only the store hosts; tunnels pinned gsa.apple.com untouched. One admin prompt; auto teardown. (macOS)
  • token import — manual path: --charles (.chlz), --har, or --paste raw headers. Cross-platform.
  • lookup / search — public iTunes API, no creds.
  • versions — lists builds; resolves newest N to version strings by default; --all for raw ids; persistent id↔version cache with --clear-cache.
  • download — current, --version-id, or --version (binary-searched). Streams from CDN, verifies md5, injects sinf + iTunesMetadata.plist, writes an installable .ipa.
  • Released via GoReleaser: GitHub binaries (macOS universal, Linux/Windows amd64+arm64) + Homebrew cask (pixel0verflow/homebrew-tap). CI + Dependabot.

3. Architecture overview

Pure Go, no cgo, single static binary. Dependencies point strictly downward; each package compiles and tests standalone.

.chlz/.har/paste ─▶ charles ─▶ Session ─▶ store (replay MZFinance) ─▶ DownloadItem ─▶ ipa ─▶ .ipa
  capture (MITM) ──────────────┘            ▲
                          credential     httpx (cookie jar, pod re-POST, plist)
  itunes (public lookup/search) ─▶ adamId

4. Problems to solve / known limitations

ItemNotes
Auth is unreproducibleThe core wall. Capture is required because login (GrandSlam SRP + SAP token mint) can't be forged. A real attempt to crack/reproduce auth is deferred.
capture is macOS-onlyKeychain trust + networksetup are darwin. Manual token import works cross-platform.
Token expiryX-Token is session-scoped; expires → re-run capture. Detected via failureType 2042/2034.
iTunes 12.6.5.3 route rejectedConsidered as a Windows/alt capture source; rejected — too fragile, relies on old auth endpoints Apple is deprecating.
Music/song token untestedAn X-Token from a Music redownload might carry over, but storefront-kind/endpoint mismatch likely rejects an app download. Unverified.
FindExternalID has no throttleBinary search is ~8 probes so 429 is unlikely; could add a small delay if it bites.
Historical builds GC'dA listed externalVersionId may 404/410 — Apple garbage-collects old assets.
